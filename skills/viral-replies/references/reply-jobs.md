# Reply jobs

One job per reply. Name it in the output.

## Jobs

| Job | Use when | Payload |
|---|---|---|
| add | Parent is right but incomplete | Mechanism, local number, named entity they skipped |
| correct | Parent has one load-bearing error | The error + the artifact. No insult. |
| translate | Parent is US/global; audience is local | Same fact, this market / this stack |
| ask | You actually need their answer | One question they are uniquely placed to answer |
| witness | You have lived the thing | One scene + one number. Not "same." |
| quote-add | Quote-tweet, not a reply | Second-order effect. Do not restate. |

## Do not

- **agree** — "This." / "So true." / "Great point." / "This is the way."
- **promo** — drop a product link under a viral post unless the parent asked for tools *and* the user said to.
- **thread-the-reply** — if it needs sequence, write an original with `viral-tweets`.
- **dunk** — dunks go viral for the dunker once, then train mutes.

## Pick

```
Parent missed a mechanism or number?     add
Parent is wrong on one fact?             correct
Parent is true elsewhere, not here?      translate
You need them to answer?                 ask
You have a scene they described?         witness
You are quoting, not replying?           quote-add
You only want to be seen agreeing?       do not draft
```

Three variants = three different jobs when the parent supports it. If only `add` is honest, write three different *payloads*, not three skins of "great insight."
