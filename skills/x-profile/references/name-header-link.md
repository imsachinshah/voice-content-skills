# Name, header, link

Text fields first. Images are notes, not generated art.

## Contents

- Display name
- Handle
- Location
- Link
- Header note
- Photo note

## Display name

Limit 50 characters. The name field is searchable; the @handle mostly is not.

Pattern: `[human name] ± [one signal people actually type]`

Good signal: a beat ("markets"), a product name, a city the feed is about.
Bad signal: "Web3 | AI | Speaker", a slogan, ALL CAPS, three pipes.

Do not replace their real name with a brand unless they asked and the feed is already that brand.

If they already have a working name, leave it and spend the rewrite on bio + pin.

## Handle

Do not recommend a rename unless the handle is unreadable (random digits, a leftover joke) *and* they asked. Handle changes cost graph. Note it; do not lead with it.

## Location

Real or omit. Do not invent "Global" as a personality. A city is useful when the beat is local (India rails, a city scene). Otherwise skip.

## Link

One link, matched to the conversion job:

- reporter → the beat's home (newsletter, blog, none)
- builder → the product
- operator → the thing they teach
- witness → omit unless there is a real home

Several destinations → one hub URL, not a stuffed bio. The bio is not a link tree.

Do not invent a domain.

## Header note

This skill does not generate a 1500×500 image.

Flag only:

- Header contradicts the bio (old company, dead product)
- Text on the header is unreadable at mobile width
- Header repeats the bio verbatim (wasted)

If they ask what the header should *say*: one line of beat, not a collage of logos. Leave image-making to them.

## Photo note

48px circle for most viewers. Flag: no face, tiny face, busy background, ancient photo vs current bio. Do not generate a headshot.
